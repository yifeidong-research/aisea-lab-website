# AI-SEA Lab Website — Product Context

## Why This Project Exists
Public-facing academic site for the newly-established AI-SEA Lab (AI Systems Engineering &
Assurance Lab) at UTS Data Science Institute, for researchers, students and industry partners —
to advertise the lab's mission, recruit PhD/HDR students, and showcase people/publications/
projects once UTS clears it for public hosting.

## Pages (all under `src/pages/`)
| Page | File | Purpose |
|---|---|---|
| Home | `index.astro` | Hero (mission, UTS Data Science Institute photo background), flagship programme, research themes summary |
| Research | `research.astro` | Aim/approach/partnership paragraphs, research-cycle diagram, research areas list, 3 detailed themes, recruitment contact box |
| People | `people.astro` | Grouped by `category` ("Core Members", "Collaborators", "PhD Students", "Master of Research Students"); photo, name, title+affiliation, bio |
| Publications | `publications.astro` | Sorted by year desc; title links to DOI |
| Projects | `projects.astro` | Flagship programme detail + programme topics; 14 individual project entries (sanitized — see note below) |
| Collaborate | `collaborate.astro` | 5 ways to work with the lab (see note below), plus a 3-step "how it works" process |
| Contact | `contact.astro` | Affiliation, faculty, address (Level 12, Building 2, UTS), public email (mailto) |
| 404 | `404.astro` | Custom not-found page |

## Key files
- `src/content/site.ts` — **single source of truth** for all content (lab info including
  physical `address`, research themes/areas, programme topics, recruitment contact,
  `people`/`publications`/`projects` arrays, `contactEmail`). Edit this file for any content
  change.
- `src/layouts/Base.astro` — shared `<head>`, header nav, footer; imports `global.css` + fonts.
- `src/components/Brand.astro` — wordmark + "Lab" tag (no logo image; UTS logo use needs
  separate authorisation, not yet sought).
- `src/components/PageIntro.astro` — shared page `<h1>` + lead paragraph.
- `src/styles/global.css` — all styling (see `systemPatterns.md` for the design-direction
  decision).
- `public/people/*.jpg` — profile photos (downloaded from UTS profile `/thumbnail` endpoints or
  external lab sites where provided by the user).
- `public/images/uts-central.jpg` — home page hero background photo (UTS Central, Building 2;
  CC BY-SA 4.0, Wikimedia Commons, photo by Robertsky, credited on-page via `.hero-credit`). See
  `systemPatterns.md` for sourcing/licensing and the grayscale+gradient-overlay treatment applied
  via CSS. (Superseded an earlier CC0 Dr Chau Chak Wing Building photo, `uts-campus.jpg`, removed
  per user's follow-up request for this specific UTS Central photo instead.)
- `public/images/research-cycle.png` — Research page diagram (minimal black-ink line-art showing
  the three research themes as a continuous cycle), AI-generated by the user from a Cline-authored
  prompt (see `systemPatterns.md`), resized from 1448×1086 to 1200×900 with `sips` for web
  delivery. Rendered via `.research-row`/`.research-figure` in `research.astro`, embedded beside
  (to the right of) the `lab.aim` paragraph in a two-column row — not a full-width banner (see
  `systemPatterns.md` for the layout revision rationale).
- `public/staticwebapp.config.json` — Azure SWA routing/headers config (404 rewrite, CSP,
  `X-Robots-Tag: noindex`). **Vestigial as of Nov 23 2026** — Azure SWA was never provisioned;
  the live site is GitHub Pages (see `systemPatterns.md`'s hosting decision), which doesn't read
  this file. Left in place in case Azure is ever added later; harmless either way.
- `scripts/verify-deployment.mjs` — post-deploy smoke test (checks all 6 pages + 404 respond
  with expected `<h1>` text). Originally run by `.gitlab-ci.yml`'s `deploy_azure` job; that
  pipeline is no longer in use (GitHub Actions `.github/workflows/deploy.yml` is the active
  deploy pipeline now and does not call this script) — kept as a manual verification tool.

## Collaborate (`src/content/site.ts` → `collaborationIntro`/`collaborationWays`/
`collaborationProcess`, page at `/collaborate/`, added to main nav between Projects and Contact)
Synthesized from the user's own brainstormed list of collaboration patterns (industry co-grant
applications; junior researchers/students seeking publication experience; grant/journal-funded
RA-style roles; academics seeking high-impact collaborators; community support requests; GenAI
production-readiness support; industry-sponsored PhD scholarships), discussed and refined in a
plan-mode conversation that started from reviewing an external lab's ("SYNTERA Research Group")
own collaboration page as a reference point — **not** to partner with that group, purely as a
model to evaluate. Reduced from the user's broader brainstorm to **5 public-facing categories**
(see `systemPatterns.md` for the full risk-screening rationale and what was deliberately
reframed/dropped): Production-readiness engineering support (the lead item — maps directly onto
the lab's own mission/flagship programme); Industry-sponsored PhD candidature; Joint grant
applications; Visiting researchers and research collaborators (merged/reframed from the user's
original "junior student publication-experience" and "academic seeking collaborators" ideas,
with explicit standard-authorship-criteria language to avoid any pay/volunteer-for-authorship
appearance); Community and translational research support. `CollaborationWay` type:
`{ title, audience, detail }`. Page follows the same `.content-row` two-column pattern already
used on `research.astro`, plus a numbered `.process-list` for the 3-step "how it works"
sequence (email → scoping conversation → written agreement before work starts).

**Follow-up (same day): expanded to 6 categories.** User asked Cline (in plan mode) whether it
could think of other collaboration methods beyond the original 5. Cline proposed 5 additional
candidates and recommended adding only the strongest two: a standalone **"Evaluation and
assurance audits"** category (a shorter, lower-commitment variant of production-readiness
support — independent evaluation/stress-testing/assurance case for a system already in or near
production, positioned second, right after the main engineering-support category since it's a
lighter entry point into the same relationship) and a closing **workshop/training note**
(`collaborationNote`) mentioning short paid workshops as an even lighter starting point. Three
other candidates Cline raised (benchmark/dataset co-development, advisory-panel membership,
standalone capstone/honours sponsorship) were deliberately left out of the page itself as too
niche/occasional for a frequent-inbound-demand page, or already adequately covered by existing
categories — see `systemPatterns.md` for the full reasoning on what was added vs. deliberately
left out.
